# Create PR Skill

현재 이슈 브랜치의 작업을 **검증된 상태로** 통합 브랜치에 올리는 PR을 만든다. TDD 이슈 사이클(CLAUDE.md)의 **7단계 "통합"** 을 담당한다 — 즉 보안 점검(6단계)까지 끝난 뒤에 호출된다.

근거: PR은 *되돌리기 어려운 외부 행위*다. 리뷰어와 CI를 끌어들이고, squash merge로 히스토리에 박힌다. 그래서 이 스킬은 두 개의 게이트를 강제한다 — **(1) 사람이 초안을 승인**해야 진행하고, **(2) E2E가 초록**이어야 push/PR로 넘어간다. 단위 테스트가 mock 뒤에서 본 것과 달리, E2E는 실제 스택을 가로지르는 회귀를 잡는 마지막 그물이다(`/e2e-write` 스킬 참조). 그 그물이 찢어진 채로 PR을 올리지 않는다.

---

## 입출력 계약

### 입력
- `$ARGUMENTS` — (선택) 이슈 번호. 없으면 브랜치명·최근 커밋에서 추론하고, 모호하면 사용자에게 묻는다.
- 현재 작업 트리 + 브랜치 상태 — `git status`, base 대비 커밋/diff.

### 산출물
- 사용자가 승인(또는 수정)한 **PR 초안** (제목·본문, 필요 시 커밋 메시지).
- E2E 통과 시: push된 브랜치 + 생성된 PR (URL 보고).
- E2E 실패 시: **PR 미생성** + 근본 원인 회피 없이 고치는 복구 경로 안내.

---

## 이 스킬의 본질 — "검증되지 않은 변경은 통합되지 않는다"

> **승인 게이트**(사람) + **E2E 게이트**(자동)를 둘 다 통과해야 PR이 나간다.

PR 생성 자체는 명령 한 줄이다. 이 스킬의 가치는 그 한 줄 *앞에* 있다:

1. **요약과 승인** — 변경을 사람이 읽을 수 있는 초안으로 압축해, 리뷰어가 PR을 열기 전에 작성자가 먼저 자기 변경을 직시하게 한다. 승인 없이 push하지 않는다.
2. **E2E 게이트** — 실제 브라우저+json-server 스택에서 사용자 여정이 도는지 확인한다. 여기서 깨지면 *프로덕션 코드나 단위 테스트에 빈틈*이 있다는 신호다. **E2E 스펙을 손봐서 초록으로 만드는 건 그 빈틈을 덮는 것**이라 절대 금지한다.

이 두 게이트를 건너뛰면 스킬은 그냥 `gh pr create` 별칭일 뿐이고, 존재 이유가 없다.

---

## base 브랜치 결정 (이 레포 특유 — 꼭 지킬 것)

이 레포의 PR은 **`main`이 아니라 통합 브랜치 `feature/<spec>`** 를 향한다 (CLAUDE.md 7단계). 이슈 브랜치(`feature/tag-create`, `feature/tag-delete` …)는 spec 통합 브랜치(`feature/tag-spec`)로 PR → squash merge → 이슈 클로즈된다.

base 추론 규칙:
1. 현재 브랜치명이 `feature/<spec>-<action>` 꼴이면 (`feature/tag-delete` → spec=`tag`), **`feature/<spec>-spec`** 을 base 후보로 삼는다.
2. `git branch -a`로 그 통합 브랜치가 실제 존재하는지 확인한다. 없으면 후보를 만들어내지 말고 사용자에게 base를 묻는다.
3. 현재 브랜치 자체가 통합 브랜치(`feature/<spec>-spec`)거나 추론이 모호하면 **임의로 정하지 말고** base를 묻는다.
4. 최종 base를 **초안에 명시**하고 승인받는다 — 잘못된 base로의 PR은 되돌리기 번거롭다.

> 절대 자동으로 `main`을 base로 잡지 않는다. 이 레포에서 `main`행 PR은 통합 브랜치→main 머지일 때뿐이고, 그건 이 스킬의 기본 흐름이 아니다.

---

## 사전 확인 (없으면 멈추고 보고)

빠르게 점검한다. 빠진 게 있으면 진행하지 말고 사용자에게 알린다:

- **`gh` 인증** — `gh auth status`. 미인증이면 `gh auth login`을 사용자가 직접(`! gh auth login`) 하도록 안내.
- **`npm run test:e2e` 스크립트 존재** — `package.json` scripts에 `test:e2e`가 있는지. **없으면 스킬을 멈추고**, `"test:e2e": "playwright test"` 추가를 제안한다 (이 스킬은 이 스크립트에 의존한다).
- **Playwright 설치** — `@playwright/test` devDependency + 브라우저. 없으면 `npm i -D @playwright/test && npx playwright install` 안내.
- **현재 브랜치가 base와 다른지** — 같으면(혹은 `main`/통합 브랜치 위에서 직접 작업 중이면) PR 대상이 없다. 보고하고 멈춘다.
- **base 대비 변경 존재** — 커밋도 미커밋 변경도 없으면 올릴 게 없다. 보고하고 멈춘다.

---

## 실행 순서

### 단계 1 — 컨텍스트 수집 + 초안 작성

다음을 모은다:
- 현재 브랜치, base 브랜치(위 "base 결정" 규칙).
- base 대비 커밋 목록: `git log --oneline <base>..HEAD`.
- 미커밋 변경: `git status --short`, `git diff <base>...HEAD --stat`.
- 이슈 번호: `$ARGUMENTS` → 없으면 브랜치명/커밋 메시지의 `(#N)`에서 추론 → 그래도 모르면 묻는다.

초안을 만든다:

- **PR 제목** — Conventional Commits 형식 + 이슈 번호. 이 레포는 commitlint(`config-conventional`)를 husky로 강제하고, **squash merge 시 PR 제목이 그대로 커밋 메시지**가 되므로 형식이 중요하다.
  - 예: `feat: 노트에 태그 추가 기능 (#3)` / `fix: 빈 태그 저장 오류 수정 (#7)`
- **PR 본문** — 아래 템플릿.
- **커밋 메시지** — *미커밋 변경이 있을 때만*. 마찬가지로 Conventional Commits 형식. 보안 점검(6단계)에서 이미 커밋됐다면 이 항목은 생략된다.

#### PR 본문 템플릿

```markdown
## 요약
<무엇을·왜 — 1~3줄>

## 변경 사항
- <핵심 변경 1>
- <핵심 변경 2>

## 테스트
- 단위: `npm test` <결과>
- E2E: `npm run test:e2e` <이 스킬에서 통과 확인>

Closes #N
```

> `Closes #N` 으로 PR 머지 시 이슈가 자동 클로즈되게 한다 (7단계 "이슈 클로즈"). base가 `main`이 아니어도 GitHub는 default 브랜치 머지 시점에 닫지만, 추적 목적상 명시한다.

### 단계 2 — 승인 게이트 (사람)

초안 전체를 보여주고 멈춘다:

```
## PR 초안 (이슈 N)

- base ← head: feature/tag-spec ← feature/tag-delete
- 제목: feat: ... (#N)

### 본문
<위 템플릿 채운 내용>

### (미커밋 변경이 있으면) 커밋 예정
- 메시지: feat: ...
- 대상: <git status 요약>

이대로 진행할까요? 제목/본문/base를 고치려면 알려주세요.
```

사용자가 승인할 때까지 **다음 단계로 가지 않는다.** 수정 요청이 오면 반영 후 다시 보여준다. (CLAUDE.md의 인간 승인 게이트 원칙)

### 단계 3 — E2E 게이트

승인되면 E2E를 돌린다:

```bash
npm run test:e2e
```

- 미커밋 변경이 있어도 **커밋은 아직 하지 않는다** — E2E가 깨지면 실패하는 코드로 커밋이 남는 걸 피한다. (단, 보안 점검에서 이미 커밋된 상태면 그대로 둔다.)
- 환경 문제(서버 미기동, 포트 충돌 등)로 *테스트 자체가 못 도는* 경우와 *테스트 실패*를 구분해 보고한다. 전자는 환경을 고치고 재시도, 후자는 단계 4.

### 단계 4 — E2E 실패 시: 중단 + 복구 경로 안내

**PR을 만들지 않는다.** push도 하지 않는다. 다음을 그대로 안내한다:

```
❌ E2E 실패 — PR 생성을 중단합니다. 근본 원인을 고치고 다시 /create-pr 하세요.

① Trace 확인: `npx playwright show-report` 로 리포트를 열어 실패 지점·스냅샷·트레이스를 본다.
   (트레이스가 잡히면 `npx playwright show-trace <trace.zip>` 로 단계별 재생)
② 레이어 판별: 실패가 어디서 났는지 가른다.
   - API: json-server 왕복/영속 (네트워크 응답, db.json 반영)
   - 렌더링: 화면에 기대한 요소가 안 뜸 (컴포넌트 분기/조건부 렌더)
   - 로직: 값/상태 계산이 틀림 (검증·변환·상태 전이)
③ 단위 테스트에 케이스 추가 (Red): 그 레이어의 단위 테스트(Vitest)에 실패를 재현하는 케이스를 먼저 추가해 빨갛게 만든다.
④ 프로덕션 코드 수정 (Green): src/ 를 고쳐 단위 테스트를 통과시킨 뒤, 다시 `/create-pr`.

⚠ 금지: E2E 스펙(e2e/*.spec.ts)을 고쳐서 통과시키지 말 것. 그건 회귀를 덮는 근본 원인 회피다.
   E2E는 "사실"이고, 고쳐야 할 건 프로덕션 코드(또는 그걸 못 잡은 단위 테스트)다.
```

여기서 스킬은 끝난다. (실제 디버깅/수정은 `/tdd-red`·`/tdd-green` 사이클로 사용자가 이어간다.)

### 단계 5 — E2E 통과 시: 커밋(필요 시) → push → PR

E2E가 초록이면 순서대로:

1. **커밋** — 미커밋 변경이 있을 때만, 승인된 메시지로:
   ```bash
   git commit -am "<승인된 커밋 메시지>"
   ```
   husky pre-commit(lint-staged)·commit-msg(commitlint)가 돈다. 훅이 실패하면 멈추고 보고 — **`--no-verify`로 우회 금지.**
2. **push**:
   ```bash
   git push -u origin <현재 브랜치>
   ```
3. **PR 생성** — base는 단계 1에서 정한 통합 브랜치:
   ```bash
   gh pr create --base <feature/spec> --head <현재 브랜치> \
     --title "<승인된 제목>" --body "<승인된 본문>"
   ```
   본문은 heredoc(`--body-file -` 또는 파일)으로 넘겨 줄바꿈을 보존한다.

### 단계 6 — 보고

```
## PR 생성 완료 (이슈 N)

- PR: <gh가 출력한 URL>
- base ← head: feature/tag-spec ← feature/tag-delete
- E2E: ✓ 통과
- 다음: 리뷰 → squash merge → 이슈 #N 클로즈 (CLAUDE.md 7단계 마무리)
```

머지·이슈 클로즈는 **사람의 결정**이다 — 이 스킬은 PR 생성까지만 하고 자동 머지하지 않는다.

---

## 절대 금지

- **E2E 스펙을 고쳐 통과시키기 금지** — 근본 원인 회피. 고칠 건 프로덕션 코드(+단위 테스트)다. (이 스킬의 핵심 규칙)
- **E2E 실패 상태로 push/PR 금지** — 게이트의 존재 이유.
- **사용자 승인 전 push/PR/커밋 금지** — 초안 승인이 먼저다.
- **`git push --force` / `--no-verify` 금지** — 히스토리 파괴·훅 우회. 훅이 막으면 원인을 고친다.
- **base를 임의로 `main`이나 추측한 브랜치로 지정 금지** — 존재 확인 + 승인. 모호하면 묻는다.
- **자동 머지 금지** — `gh pr merge` 호출 안 함. 머지는 사람이 결정.
- **이슈 사이클 단계 건너뛰기 금지** — 이 스킬은 보안 점검(6단계) *이후*에 온다. 앞 단계가 안 끝났으면 보고하고 멈춘다.

---

## 자주 하는 실수

- ❌ base를 `main`으로 두고 PR 생성 → 이 레포는 `feature/<spec>` 통합 브랜치행이다. 잘못된 base는 되돌리기 번거롭다.
- ❌ E2E가 깨졌는데 `e2e/*.spec.ts`의 단언을 느슨하게 바꿔 초록 만듦 → 회귀를 덮음. 금지.
- ❌ 승인 없이 바로 `gh pr create` → 작성자가 자기 변경을 직시하는 기회를 잃고, 잘못된 제목/본문이 squash 커밋에 박힌다.
- ❌ PR 제목을 비-conventional로 작성 → squash merge 시 commitlint 규약을 깬 커밋이 main에 남는다.
- ❌ E2E *환경 오류*(서버 안 뜸)를 *테스트 실패*로 오인해 단계 4 복구 경로로 보냄 → 환경부터 고친다.
- ❌ `test:e2e` 스크립트가 없는데 `npx playwright test`로 몰래 우회 → 사전 확인에서 멈추고 스크립트 추가를 제안한다(일관된 진입점 유지).

---

## 끝맺음

PR URL을 사용자에게 보고하고, 남은 사람 결정(리뷰 → squash merge → 이슈 클로즈)을 한 줄로 안내한다. 이 스킬은 *검증된 변경만 통합 후보로 올린다* — 그 이후는 사람의 몫이다.
